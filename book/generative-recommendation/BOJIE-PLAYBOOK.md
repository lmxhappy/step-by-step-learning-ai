# 若李博杰写《深入理解生成式推荐》会怎么排

> 内部对照稿：把他的《深入理解 AI Agent》开源书路子，映射到生成式推荐。  
> （你提到的「AI Infra」按同一套「深入理解 + 开源书」打法理解；他已公开爆款主线是 Agent 书。）

## 1. 先立公式，再写章

Agent 书：`Agent = LLM + 上下文 + 工具`  
生成式推荐书：`GenRec = SID + Generator + Conditioning + Serving Harness`

全书任何工业案例都要能填进这四格；填不进就说明还在讲「可替换的旧精排背景」。

## 2. 三根支柱，不要论文串烧

错误排法：OneLive → TGR → CONGRATS → EAGER（读者以为是公众号合订本）。

正确排法（李博杰式）：

1. **标识支柱**：没有稳定 SID，生成式推荐只是换皮检索  
2. **生成支柱**：目标函数、似然陷阱、场景生成器  
3. **条件支柱**：序列、Reason、query——生成时看什么  

然后才是进阶：重排/整页、Serving、评估与自动科研。

案例论文挂在支柱下当「实验课」，不当目录本身。

## 3. 「实验」怎么做（你没有 100 个训练 demo）

他：章末可跑代码。  
你：章末三类清单，读者拿自己的业务就能勾：

- 指标对照表（文中数字 → 我司看板）  
- 消融序（若只做一刀）  
- 上线门禁（请求是否变重、近线能否扛、失败回退）

## 4. 叙事顺序：实践在前，命名在后

每章先写「线上疼点」，再出 TGR/CONGRATS/OneLA 名字。  
避免：先甩名词，再解释。
